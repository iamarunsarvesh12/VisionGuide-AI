# Module 10 — Offline Audio Guidance

## 1. Module Purpose
`Module 10 — Offline Audio Guidance` serves as the final acoustic presentation layer of the **VisionGuide AI** assistive navigation framework. It transforms non-verbal contextual navigation decisions (`DecisionResult` / `NavigationCommand`) produced by Module 09 into short, clear, deterministic spoken directional instructions (`"Left"`, `"Right"`, `"Forward"`, `"Stop"`) delivered completely offline to laptop speakers or connected Bluetooth audio headsets/earbuds.

## 2. System Architecture
```
+-------------------------------------------------------------+
|              Module 09 Context-Aware Decision Engine         |
+-------------------------------------------------------------+
                              |
                              v [DecisionResult]
+-------------------------------------------------------------+
|                 OfflineAudioGuidance Interface               |
+-------------------------------------------------------------+
  |-- 1. Command Validation (LEFT, RIGHT, FORWARD, STOP)
  |-- 2. Audio Message Mapping ("Left", "Right", "Forward", "Stop")
  |-- 3. Priority Arbitration (STOP: Critical=100, LEFT/RIGHT: High=80, FORWARD: Normal=50)
  |-- 4. Command Repetition Suppression & Interval Control
  |-- 5. Non-Blocking Priority Queue & Background Worker Loop
  v
+-----------------------------+     +-----------------------------+
|    Pyttsx3 (SAPI5) Engine   |     |   Audio Output Device Mgr   |
|   Offline Speech Synthesis  |     |  System Audio / Bluetooth   |
+-----------------------------+     +-----------------------------+
```

## 3. Inputs
- `DecisionResult`: Output object from Module 09 containing `command` (`"LEFT"`, `"RIGHT"`, `"FORWARD"`, `"STOP"`), `confidence`, `decision_score`, `reason`, and `timestamp`.
- String commands (`"LEFT"`, `"RIGHT"`, `"FORWARD"`, `"STOP"`) or `NavigationCommand` enum.
- `AudioConfiguration` parameters loaded from `config/config.yaml`.

## 4. Outputs
- `AudioResult`: Structured feedback model containing `success`, `command`, `message`, `output_device`, `latency_ms`, `timestamp`, and `error`.
- Physical acoustic speech output generated by Windows SAPI5 (`pyttsx3`) or Mock TTS engine.

## 5. Command Mapping
To maintain zero ambiguity for visually impaired users, dynamic LLM sentence generation is strictly avoided in favor of deterministic mapping:

| Navigation Command | Spoken Output | Priority Level | Default Priority Score |
| :--- | :--- | :--- | :--- |
| **`STOP`** | `"Stop"` | CRITICAL | 100 |
| **`LEFT`** | `"Left"` | HIGH | 80 |
| **`RIGHT`** | `"Right"` | HIGH | 80 |
| **`FORWARD`** | `"Forward"` | NORMAL | 50 |

## 6. Safety Priority Arbitration
Safety commands take absolute precedence over directional guidance:
- `STOP` (100) > `LEFT`/`RIGHT` (80) > `FORWARD` (50).
- When a `STOP` command arrives, any active speech playback of lower priority is immediately interrupted (`tts_engine.stop()`), pending queues are cleared, and `"Stop"` is spoken instantly.

## 7. Command Repetition Suppression & Temporal Stability
To prevent continuous chatter when navigation directives remain steady across visual frames (e.g. repeated `FORWARD` directives):
- Repetition suppression evaluates time elapsed since last spoken for that specific command.
- Default intervals:
  - `FORWARD`: 2.0s
  - `LEFT`: 1.5s
  - `RIGHT`: 1.5s
  - `STOP`: 0.8s
- **Command Changes**: If the decision transitions (e.g., `FORWARD` → `LEFT` or `LEFT` → `STOP`), the new command is spoken immediately without suppression.

## 8. TTS Engine Architecture
- **`Pyttsx3TTSEngine`**: Leverages Microsoft SAPI5 on Windows 11 completely offline. Automatically initializes Windows COM interfaces (`CoInitialize`), queries installed voice profiles, configures rate/volume, and synthesizes speech.
- **`MockTTSEngine`**: Fast, silent mock engine for deterministic automated unit testing and performance benchmarking.

## 9. Bluetooth Audio Endpoint Handling
- `AudioOutputDevice` queries active Windows default audio render endpoints (laptop speakers, Bluetooth headsets, earbuds).
- Bluetooth device disconnection is handled gracefully without throwing unhandled exceptions or crashing perception/decision pipelines.

## 10. Error Handling & Fail-Safe Operation
- Unrecognized or malformed commands return `AudioResult(success=False)` safely without raising exceptions.
- TTS hardware initialization failures fall back to silent logging mode without interrupting perception tasks.

## 11. Configuration (`config/config.yaml`)
```yaml
audio_guidance:
    enabled: true

    tts:
        engine: "sapi5"
        voice: ""
        rate: 170
        volume: 1.0

    repetition:
        enabled: true
        forward_interval_sec: 2.0
        left_interval_sec: 1.5
        right_interval_sec: 1.5
        stop_interval_sec: 0.8

    priority:
        stop: 100
        left: 80
        right: 80
        forward: 50

    output:
        use_system_default: true
```

## 14. Hardware Migration & Portability
The `AudioGuidanceInterface` and `TTSEngineInterface` abstractions ensure that when migrating from laptop CPU (Windows SAPI5) to mobile wearable hardware (Android TTS / Bluetooth earbuds), the core decision-to-audio arbitration engine remains identical.

## 15. Privacy & Offline Operation
All text-to-speech synthesis and device audio routing execute 100% locally on device hardware. No cloud services, external web APIs, or network connections are utilized.

## 16. Technical Innovations & Patent Considerations
- **Deterministic Spoken Translation**: Real-time conversion of contextual multi-hazard free-space navigation scores into minimal single-word acoustic directives.
- **Priority-Based Safety Arbitration**: Real-time interrupt mechanism ensuring `STOP` directives override active directional speech.
- **Temporal Repetition Control**: Context-aware suppression suppressing redundant continuous commands while guaranteeing immediate output on state changes.
- **Edge Execution & Abstraction**: Hardware-decoupled acoustic guidance architecture optimized for real-time edge execution.
